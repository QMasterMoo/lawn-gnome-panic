# Stack

Web first: a prototype that runs in a browser can be shared as a link and needs no install. Reach for Unity only when an idea needs something the web stack does badly, such as heavy 3D or console-style physics.

## Default: Vite + TypeScript + Phaser 4

| Need | Use | Why |
|---|---|---|
| Dev server and build | `vite` | Instant reload; `vite build` gives a static folder you can host anywhere (itch.io, GitHub Pages). |
| 2D game framework | `phaser` (v4) | Scenes, arcade physics, input, tweens, particles, cameras, audio, tilemaps, all built in. |
| Language | TypeScript, `strict` | Catches contract mismatches between parallel workers at `tsc` time. |

Versions checked on 2026-11-11: phaser 4.2.1, vite 8.3.8, typescript 7.0.2.

## Other TypeScript options, by kind of idea

| Idea | Library |
|---|---|
| 3D | `three` (rendering), with `@react-three/fiber` if UI-heavy. `@babylonjs/core` for a fuller engine (physics, GUI, inspector). |
| Physics beyond arcade | `@dimforge/rapier2d-compat` / `rapier3d-compat` (WASM, deterministic), or `matter-js` (built into Phaser). |
| Lots of sprites, custom engine | `pixi.js` |
| Grid, tactics or turn-based logic | Plain TS state plus any renderer; keep rules in pure functions so they unit-test with `vitest`. |
| Multiplayer | `colyseus` (authoritative rooms) or `peerjs` (WebRTC, P2P). |
| Procedural generation | `simplex-noise`, `seedrandom` |
| Level editing without a game editor | Tiled (free) exports JSON that Phaser loads natively with `this.load.tilemapTiledJSON`. LDtk is a free alternative. |
| Audio without asset files | WebAudio oscillators (see `games/sample-dodge/src/audio.ts`); `jsfxr` for retro sound effects in code. |
| Animation without an editor | Spritesheets from free packs (frame ranges in code: `this.anims.create`), or Phaser tweens. For 3D, glTF models with built-in clips played by name. |

## Unity (when needed), without hand editing

Goal: the editor is only ever opened to look, never to build.

- Create projects and build headless: `Unity.exe -batchmode -nographics -projectPath unity/<name> -executeMethod Build.WebGL -quit -logFile -`.
- Build scenes in code: one bootstrap `MonoBehaviour` or an `[InitializeOnLoad]` editor script creates GameObjects, components and lights. Commit scripts, not hand-made scene changes.
- Animation without the Animator window: import glTF/FBX models that already contain named clips (Quaternius, Kenney), and play them from code with the `Animation` component or the Playables API (`AnimationClipPlayable`). An `AnimatorController` can also be generated by an editor script (`AnimatorController.CreateAnimatorControllerAtPath`).
- Packages via `Packages/manifest.json` (text), for example `com.unity.cloud.gltfast` for glTF import.
- Tests: `-runTests -testPlatform EditMode`.

No Unity project exists yet; this section is the plan for the first one.
